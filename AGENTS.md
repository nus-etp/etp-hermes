## What this is

A scheduled hermes-agent deployment. No app to build/test — the "product" is the daily signal set under `signals/` (dated updates, agent supplements, per-company living briefs). Behavior is configured by editing the prompts, the deterministic pre-step scripts, and the data files.

## Layout

`scripts/bootstrap-hermes.sh` copies `hermes/` verbatim into `$HOME/.hermes/`. Everything outside `hermes/` is repo-side, referenced by the prompts at runtime.

- `hermes/` → `~/.hermes/` (config, memories, optional skills)
- `prompts/{ingest,agent_supplement,synthesis,infographics}.md` — the four layer prompts fed to `hermes -z`
- `data/{companies,feeds,sectors}.json` — watchlist + firehose feeds + sector taxonomy
- `scripts/` — deterministic pre/post-steps (preflight, jina prefetch, candidate collection, watchlist slicing, gap-fill rotation, exclusion filtering, metrics)
- `signals/updates/`, `signals/agent/`, `signals/briefs/`, `signals/seen-urls.txt`, `signals/dropped-urls.txt` — layer outputs; the only paths the agents may write
- `signals/metrics/`, `data/metrics/` — deterministic public-metrics charts + series (no LLM)
- `site/` — static frontend (pnpm/turbo workspace, deployed via `pages.yml`)
- `.github/workflows/hermes-sync.yml` — daily 13:00 UTC cron

## Local run

```bash
export DEEPSEEK_API_KEY=...      # primary; NVIDIA_API_KEY also works (first fallback)
bash scripts/bootstrap-hermes.sh
python3 scripts/preflight-feeds.py        # change detection → data/changed-sources.json
python3 scripts/jina-reader.py            # html_scrape prefetch → data/jina-items.json
python3 scripts/collect-candidates.py     # feed parse + triage + dedup → data/candidates.json
hermes -z "$(cat prompts/ingest.md)"      # Layer 1: relevance pass only
rm -f data/agent-reached.txt                     # per-run Layer 2 progress log
python3 scripts/select_gapfill_queue.py
python3 scripts/slice_companies.py --layer agent
hermes -z "$(cat prompts/agent_supplement.md)"   # Layer 2
python3 scripts/slice_companies.py --layer synthesis
hermes -z "$(cat prompts/synthesis.md)"   # Layer 3
```

## Pipeline (one GHA run)

1. **Deterministic collection** — `preflight-feeds.py` (conditional GETs → changed-source whitelist) → `detect-dead-feeds.py` (classify dead/stale feeds → `signals/feed-health.md`) → `jina-reader.py` (html_scrape → markdown items) → `collect-candidates.py` (fetch+parse all changed rss/github_org/lever_jobs sources, entity-linked triage against `name + aliases + match_terms` minus `exclude_terms` with the generic-term guard, date windows, dedup against `signals/seen-urls.txt` + the live entries of `signals/dropped-urls.txt`, Parallel-reader fallback for unreachable firehose/rss feeds) → `data/candidates.json`. **No LLM involved up to here.**
2. **Layer 1 — ingest** (`prompts/ingest.md`) — LLM relevance pass over `candidates.json` only (plus fallback fetches for pages the heuristics couldn't parse). The judgment is stated as a goal + worked examples ("freed judgment"), not enumerated drop-lists — see the A/B section below. Firehose bias: drop. Per-company bias: keep. Writes `signals/updates/<UTC-date>.md`; appends **kept** dedup keys to `seen-urls.txt` (permanent) and **dropped** ones to `dropped-urls.txt` (date-stamped, TTL'd — see the dedup-split bullet below).
3. **Layer 2 — agent supplement** (`prompts/agent_supplement.md`) — dynamic search over today's deepen companies + the gap-fill queue, reading the `data/agent-companies.json` slice. **Fewer companies, deeper**: `select_gapfill_queue.py` queues 18/day (was 60) and the prompt budgets ~4–6 of the 100 ops per gap-fill company (search + the mandatory date/link verification fetches) instead of the old 1–2, which was arithmetic that couldn't work. Processing order is (1) deepen — today's news is only followable today, (2) queued companies **with** `open_questions`, where answering each question is the first objective of the pass, (3) the remaining queued companies. Kept items that settle a question carry an `Answers: "<question>"` sub-line that Layer 3 uses to retire it. The agent appends each finished company to `data/agent-reached.txt` so the rotation is stamped honestly (see below). Workflow-guarded: skipped when there is no cohort.
4. **Layer 3 — synthesis** (`prompts/synthesis.md`) — merges today's signals into `signals/briefs/<slug>/LIVING_BRIEF.md`, reading the `data/touched-companies.json` slice. Brief-quality rules live in the prompt: a new-brief bar (≥3 third-party signals or one material event — homepage/Crunchbase/LinkedIn pages don't count), job postings aggregated into a single `### Hiring` subsection (rolled-up read + ≤3 strategically revealing postings), corroborating coverage appended as "Also reported by:" instead of new bullets, a required `_Last material event:_` line in the Thesis, a required `## Funding history` section (`_No disclosed funding._` fallback), and retire-answered-open-questions-before-appending (cap ~4). A deterministic post-step, `scripts/normalize_briefs.py`, then date-sorts each brief's signal sections and rotates >30-day items into Older signals. Workflow-guarded: skipped when Layers 1–2 produced nothing today.
5. **Layer 4 — infographics** (`prompts/infographics.md`) — for every brief that gained a **genuinely new signal** this run, invoke the bundled `creative-baoyu-infographic` skill and copy the PNG to `signals/briefs/<slug>/infographic.png`. The changed set is *not* recomputed by the prompt — a deterministic pre-step, `scripts/select_infographic_queue.py`, decides it and writes `data/infographic-queue.json` (`{changed, missing}`); the prompt reads that file. Self-healing: remaining cap slots backfill briefs whose `infographic.png` is missing from a prior failure (oldest-first by last-commit time). Capped at 8 per run; a `pngquant` workflow step then compresses the new PNGs (committed PNGs are megabyte-scale otherwise). Skill intermediates under `infographic/` are gitignored.

Tune *judgment* by editing the prompts and the per-company `description` / `match_terms` / `exclude_terms` fields in `data/companies.json` (that's where ticker collisions, same-name entities, and generic-word disambiguation are encoded — `description` for the LLM's relevance pass, `match_terms`/`exclude_terms` for the deterministic triage that runs before it). Tune *mechanics* (parsing, dedup, date windows, triage) in `scripts/collect-candidates.py` and the matching rules in `scripts/entity_terms.py` — the prompts no longer do mechanical collection.

## A/B experiment — concluded (v2 "freed judgment" promoted 2026-06-29)

The Layers 1–2 A/B tested "freed judgment" (relevance stated as a goal + worked examples; Layer 2 plans its own queries) against the old enumerated drop-lists / query templates. **v2 won** the pre-registered McNemar test (n=75 discordant pairs, p=0.0004; v2 right 53 / v1 right 22; volume guardrail ok at 0.77×) and its judgment sections were promoted verbatim into the production prompts (`prompts/{ingest,agent_supplement}.md`). The parallel v2 arm was then retired:

- **Removed**: `prompts/v2/`, `signals/v2/`, the v2 + A/B-scoring steps and the `v2` dispatch input in `hermes-sync.yml`, the `agent-v2` slice layer, and the v2 path-routing in `filter_exclusions.py`.
- **Kept (dormant harness)**: `scripts/ab_{compare,judge,stats,backfill,llm}.py`, `scripts/ab_arms.py` (registry, now `DEFAULT_CHALLENGERS = ()`), their unit tests, and the `signals/ab/` history (`metrics.jsonl`, `disagreements.jsonl`, `report.md`, `significance.json`) — the frozen record of the v1-vs-v2 run. These scripts are written against the v1/v2 names; a future experiment re-wires them per the **ab-test skill** checklist.
- **Starting the next experiment**: add a `v3` challenger — `prompts/v3/{ingest,agent_supplement}.md` (copy production, change one variable), `signals/v3/` (seed seen-urls from `signals/seen-urls.txt`), the per-arm workflow steps (continue-on-error, Langfuse env-swap), and register it. See `.claude/skills/ab-test/SKILL.md` for the full playbook and decision rule (promote at `significant` + guardrail `ok`).

## Non-obvious

- Change-detection preflight: `scripts/preflight-feeds.py` runs before Layer 1 and sends conditional HTTP requests (ETag/Last-Modified + body-SHA256 fallback) against every preflightable source URL. It writes `data/feed-cache.json` (per-URL state, gitignored, kept across runs via the GHA `feed-cache-*` cache key) and `data/changed-sources.json` (the URL whitelist the ingest prompt is allowed to fetch). `html_scrape` sources are not preflighted — they're always listed as changed. For local runs, invoke `python3 scripts/preflight-feeds.py` before `hermes -z` to get the same skip behavior.
- html_scrape reader prefetch: `scripts/jina-reader.py` (name kept from its Jina days) runs between preflight and candidate collection. For every html_scrape URL preflight marked changed, it fetches the page through the **keyless Parallel Search MCP** `web_fetch` tool with `full_content: true` (`https://search.parallel.ai/mcp`, the same free endpoint hermes uses as its web surface — `initialize` → `notifications/initialized` → `tools/call`, stdlib urllib). It replaced `r.jina.ai` in 2026-10 after the `JINA_API_KEY` balance ran out and every call returned HTTP 402 for a month, silently starving `pre_extracted` items. It caches the markdown under `data/jina-cache/` (gitignored, GHA cache key `jina-cache-*`), and runs a heading→link heuristic to write structured items into `data/jina-items.json`. `collect-candidates.py` folds those into `data/candidates.json` flagged `pre_extracted: true` (the relevance pass auto-keeps them); html_scrape URLs jina missed are listed under `llm_fetch_required` so the ingest prompt parses them itself. Daily call budget: `JINA_DAILY_BUDGET` (default 80). **Keyless by policy** (a Parallel key means metered calls); the anonymous rate limit is handled in `jina_fallback.py` by reusing one MCP session per process (each fetch used to be three HTTP calls — initialize, initialized, tools/call — so 28 pages were 84 requests in ~70s and 22/28 came back 429 on 2026-10-05), pacing calls `READER_MIN_INTERVAL_SECS` apart (default 2), and retrying 429/503 with `Retry-After` or a 5/15/45s backoff before giving up. Rate alarm: when ≥`JINA_ERROR_RATE_ALARM` (default 0.5) of attempted fetches fail (min 4 attempts) the script still writes its outputs but exits 1 so the `continue-on-error` step shows red instead of a green run that produced nothing — the Jina 402 outage ran silently for a month because every call was allowed to fail. Fails open everywhere — HTTP/protocol error, empty result, or extraction miss all degrade to the LLM-parse path. A failed fetch is stamped `failed_at` (never `fetched_at`), so an older cached page is not re-served as a fresh hit on the next run. For local runs invoke `python3 scripts/jina-reader.py` after preflight. The `fetch_reader` + heading→link `extract_items` heuristic live in the shared `scripts/jina_fallback.py` module (imported here and by the `collect-candidates.py` dead-feed fallback). Because `pre_extracted` items skip the relevance judgment, the heuristic rejects page chrome itself: footer/nav headings (`NAV_HEADINGS` — `Product`, `Company`, `Legal`, `Country/region`…), listing section titles (`SECTION_HEADING_RE` — `Synectify News`, `Blog`, `In the News`), and utility links (`UTILITY_PATH_SEGMENTS`/`UTILITY_PATH_MARKERS` — `/cart`, `/workspace`, `/contact`, `/privacy-policy`, newsletter sign-ups); `**` emphasis is stripped from headlines. Parallel's markdown includes the full page chrome that Jina used to trim, and on 2026-10-04 `Country/region → /cart` and `Product → /workspace` reached Layer 1 as auto-keep items.
- Candidate collection: `scripts/collect-candidates.py` does all of Layer 1's mechanical work (fetch/parse changed feeds, entity-linked triage, date windows, dedup against `signals/seen-urls.txt` + the non-expired half of `signals/dropped-urls.txt`, GitHub bot/chore filtering) and writes `data/candidates.json` — including a `companies` map carrying *only* matched companies' descriptions. Both ingest arms read just that file; this is what keeps the ~300KB `companies.json` and ~300KB `seen-urls.txt` out of model context (they used to cost ~150K input tokens per session turn). Per-source fetch failures land in `fetch_failed` for the prompt to retry (fail open); a script crash fails the workflow step (fail loud) because both arms depend on its output.
- Entity-linked triage: `scripts/entity_terms.py` (shared module, pure stdlib) holds the matching rules `collect-candidates.py` applies to every item. Positive terms are `name + aliases + match_terms`; each is graded **strong** (contains a digit or a dot — `assist.id`, `x0pa`; or spans multiple words — `Bright Sight`; or is a curated `match_term`; or is longer than `WEAK_MAX_LEN`=5 chars) or **weak** (short, or a member of the built-in `COMMON_WORDS` English/business word list — `arch`, `ava`, `alpha`, `amble`, `assist`, `emerge`, `platform`…). Acceptance: a strong term may match anywhere in `title + description`, a weak term **only in the title**; weak-in-description-only is the `Arch`-matched-a-stablecoin-story false-positive class and is dropped. 36 of 488 watchlist entries currently have no strong term, i.e. are title-only. `exclude_terms` (whole-word, same regex style) veto a company's match for an item regardless of what matched, on *all* paths including per-company sources and the Jina fallback — `scripts/filter_exclusions.py` stays as a post-hoc backstop for LLM-fetched items the collector never saw. A curated `match_term` is never upgraded to strong if it is itself a dictionary word. Stats: `excluded_by_terms`, `weak_term_suppressed`. Tests: `tests/scripts/test_entity_terms.py` (classifier) + the guard/exclude cases in `tests/scripts/test_collect_candidates.py`.
- Match-term generator: `scripts/generate_match_terms.py` is an operator-run one-off (not in any workflow) that drafts the two fields above for the whole watchlist. Pass 1 is deterministic — the company's own domain harvested from its `sources[]`/`identifiers` URLs (third-party hosts and brandless sub-domains like `press.` stripped). Pass 2 is one DeepSeek call per company through `scripts/ab_llm.py` (`DEEPSEEK_API_KEY`), asking for founder/product `match_terms` and, for generically-named companies, disambiguating `exclude_terms`; fail-open per company (error or unparseable reply → keep the deterministic terms and move on). Writes `data/match-terms-draft.json` (gitignored) and never edits the watchlist; `--merge` then unions the draft into `data/companies.json` in place (key order and formatting preserved, case-insensitive dedup) for review as a PR diff. Flags: `--no-llm`, `--only <substr>`, `--generic-only` (just the entries with no strong term), `--limit N`, `--sleep S`. Local: `python3 scripts/generate_match_terms.py --generic-only --limit 20` then `python3 scripts/generate_match_terms.py --merge && git diff data/companies.json`.
- Dead-feed reader fallback: before a firehose/rss feed is written off to `fetch_failed`, `collect-candidates.py` refetches it through the same keyless Parallel reader (`scripts/jina_fallback.py`, shared with `jina-reader.py`), which reaches hosts the GHA runner can't or that gate it (The Low Down 403s every UA in the ladder but Parallel returns its RSS). When the reader hands back a raw feed (XML, often in a code fence, with `&amp;` mangled to `&;`), `as_feed_xml` repairs it and it is parsed as a real feed with titles/descriptions/dates; anything else goes through the heading→link heuristic. Recovered items are flagged `via_jina_fallback: true` (field names kept). Keyless, no secret; bounded per run by `JINA_FALLBACK_BUDGET` (default 25). Only `firehose`+`rss` are recovered — `github_org`/`lever_jobs` need fields (author/id, JSON) Markdown can't carry, so they stay in `fetch_failed`. Disabled in `collect()` unless a `reader=` is passed (the default keeps existing callers/tests at direct-fetch-only). Recovered URLs land in `jina_recovered`; stats add `jina_recovered`/`jina_candidates`.
- User-Agent ladder: `collect-candidates.py`'s `fetch()` and `preflight-feeds.py`'s `check_url()` both walk `UA_LADDER` — honest `etp-hermes-*` UA first, then a desktop-Chrome UA, then Googlebot, then a set of verified-effective agent-fetcher UAs (Gemini's literal `Google`, `OpenAI File Downloader`, GPTBot, `Claude-User`, PerplexityBot, xAI's `XaiImageApiFetch`) — retrying only on gate statuses (`GATED_STATUSES = {401, 403, 429}`); any other HTTP error (404, 5xx) or a network failure re-raises immediately so the ladder never wastes attempts. Many feed hosts front-ended by Cloudflare 403 an unknown bot UA but serve the identical public RSS/Atom to a browser (Tech in Asia: honest UA→403, Chrome UA→200 with the real 36-item feed) — and no single UA wins everywhere (Tech in Asia 403s Googlebot; some paywalled news do the reverse), which is why it's a ladder. This runs *before* the Jina fallback below, so a UA-gated feed is recovered by direct fetch without spending Jina budget, and preflight now sees the real body (ETag/SHA change-detection works) and resets the dead-feed streak instead of flagging the feed dead forever. `github_org`/`lever_jobs` also benefit since they share `fetch()`. Genuinely dead feeds (Microtube = 404 to every UA) are unaffected — prune those in `data/feeds.json`. Tests: `test_fetch_ua_ladder_*` (collect), `test_ua_ladder_*` (preflight).
- Dead-feed detector: `scripts/detect-dead-feeds.py` runs right after preflight, reads the `consecutive_failures` (reset on 200/304, incremented on HTTP/network error — added to `preflight-feeds.py`) and `last_changed` state in `data/feed-cache.json`, and classifies every source **dead** (≥`DEAD_FEED_FAIL_THRESHOLD`, default 3, consecutive failures) or **stale** (reachable but no new items in >`DEAD_FEED_STALE_DAYS`, default 45). Writes `signals/feed-health.md` (committed, human report, worst-first) + `data/dead-feeds.json` (gitignored machine list). Pure observability — `continue-on-error`, never gates the run; the actual recovery is the inline r.jina.ai fallback above, so a dead `firehose/rss` row is one even Jina couldn't reach. Local: `python3 scripts/detect-dead-feeds.py` after preflight.
- Watchlist slices: `scripts/slice_companies.py --layer agent|synthesis` writes `data/agent-companies.json` / `data/touched-companies.json` — full company entries for just that layer's cohort (gap-fill queue + deepen H2s for Layer 2; today's updates/agent headings for Layer 3). The prompts read the slice and fall back to `companies.json` only if it's missing. All slice/candidate files are gitignored, regenerated per run.
- Brief normalization: `scripts/normalize_briefs.py` runs right after Layer 3 in the workflow and enforces the briefs' formatting invariants deterministically (the synthesis LLM drifts): Recent/Older signal bullets sorted descending by date, Recent items older than 30 days (`--days`) rotated into Older, `_none_` placeholders added/removed. Block internals are preserved byte-for-byte; a `### Hiring` subsection at the end of Recent signals is preserved verbatim and never rotates. Fails open per file (unparseable brief → stderr SKIP, exit 0), idempotent, doesn't rewrite unchanged files. Local: `python3 scripts/normalize_briefs.py [--check] [--today YYYY-MM-DD]`.
- Infographic queue selection: `scripts/select_infographic_queue.py` runs right after `normalize_briefs.py` and before Layer 4, and decides which briefs get a fresh (expensive, ~1.3MB) infographic. The old Layer 4 prompt regenerated for *any* brief whose `LIVING_BRIEF.md` differed from `HEAD`, which over-fired: `normalize_briefs.py` reorders/rotates signal blocks (a Recent→Older rotation is a diff but not new content), and synthesis bumps `_Last updated:_`, appends "Also reported by:" sources to existing signals, and retires open questions — none of which change what the image depicts. This pre-step instead marks a brief **material** only when the working tree carries a *genuinely new signal*: a dated bullet — in either the Recent or Older section — whose identity (`signal_key` = date + headline with any trailing `(Also reported by: …)` stripped) is absent from the committed brief, or a changed `### Hiring` roll-up; a brand-new brief with any signal counts (first-run creation). Writes `data/infographic-queue.json` (`{changed, missing}`, gitignored) that `prompts/infographics.md` reads instead of running its own git diff. `missing` = briefs with a `LIVING_BRIEF.md` but no `infographic.png` (prior Layer 4 failure), oldest-first by last-commit time, de-duped against `changed`. Reuses `normalize_briefs.py`'s section parser; fails open per brief (unparseable/git error → assume material, regenerate rather than serve a stale image). Runs after normalize so its rotation isn't mistaken for new content; fails loud on crash (a real bug). Tests: `tests/scripts/test_select_infographic_queue.py`. Local: `python3 scripts/select_infographic_queue.py`.
- Open-questions loop: `select_gapfill_queue.py` harvests up to 4 `## Open questions` bullets from *every* not-covered candidate's living brief (fail-open to `[]`) and uses them twice. First as an **ordering key**: the queue sorts by `(has open questions DESC, last_queried ASC, name ASC)`, so brief-holding companies with unanswered questions take the 18 slots before pure-cold companies do — 159 questions across 58 briefs had accumulated with ~zero ever retired, because under the old ordering they only got the tail of the op budget. Then as **content**: the queued companies' questions are written to `data/agent-open-questions.json` (gitignored) as `[{name, open_questions}]`. Layer 2 researches them questions-first and marks a kept item that settles one with an `Answers: "<question>"` line under the URL; Layer 3 parses that marker (`prompts/synthesis.md` step 2 → `ANSWERED[c.name]`) and deletes the matching brief question before appending new ones. `signals/agent-queue.txt` stays names-only, so the layer guard and downstream scripts are unaffected.
- Honest rotation stamping: `update_gapfill_state.py` stamps `last_queried` only for the intersection of `signals/agent-queue.txt` and `data/agent-reached.txt` — the per-run file Layer 2 appends a company name to as it *finishes* each one. Companies the agent never reached (budget exhausted, or a crash — Layer 2 is `continue-on-error`) keep their turn instead of burning a rotation slot, which is what previously let a company be marked "queried" 60-at-a-time without ever being researched. Fails open: no reached file → stamp the whole queue, since rotation liveness beats precision if the model forgets to write it. Reached names not in the queue, and queued names no longer watchlisted, are ignored with a note. The workflow `rm -f data/agent-reached.txt` right before `select_gapfill_queue.py` so the file is always this run's; it's gitignored. Local: the file lives at `data/agent-reached.txt`, delete it before a manual Layer 2 run.
- seen/dropped membership for the agentic layers is checked per URL with `grep -Fxq '<key>' signals/seen-urls.txt || cut -f2- signals/dropped-urls.txt | grep -Fxq '<key>'`, never by reading either file into context (the prompts say so explicitly).
- API keys: `bootstrap-hermes.sh` copies `NVIDIA_API_KEY`, `DEEPSEEK_API_KEY`, `ZAI_API_KEY` and `XIAOMI_API_KEY` verbatim into `~/.hermes/.env` (each bundled provider reads its own name) and fails if neither `DEEPSEEK_API_KEY` (primary) nor `NVIDIA_API_KEY` (first fallback) is set — either alone still yields a working chain.
- Provider failover: the primary is `deepseek` / `deepseek-flash` (DeepSeek direct); `fallback_providers` is `nvidia`/`deepseek-ai/deepseek-v4.1-flash` → `zai`/`glm-4.7-flash` → `xiaomi`/`mimo-v2.5`. Swapped 2026-10-31: in October's Langfuse traces NIM returned RateLimitError/APIConnectionError/APIStatusError on the first 2–6 calls of almost every `hermes -z` session (~180s each, ~6 min wasted per session before the chain took over), while `deepseek-flash` served 139M tokens with 0 null generations and `glm-4.7-flash` had 73 null calls of 562. `agent.api_max_retries: 1` (default 3) makes a throttled/dead provider fail over after a single attempt. When the primary is exhausted mid-turn (rate-limit, billing, 5xx, or connection failure after `agent.api_max_retries`), Hermes' `-z`/oneshot path (`hermes_cli/oneshot.py` reads `fallback_providers` → passes it as the agent's `_fallback_chain`) swaps to the next entry. Failover is **turn-scoped** — each new turn restores the primary first. Each entry reads its own key from `~/.hermes/.env`, seeded by `bootstrap-hermes.sh` from the matching GHA secret; a missing key resolves to no client and the entry is skipped. Rollback: set `model.provider: nvidia` / `model.default: deepseek-ai/deepseek-v4.1-flash`.
- `execute_code` disabled: `agent.disabled_toolsets` also lists `code_execution` (the toolset that owns `execute_code`; hermes subtracts it at tool granularity). When `glm-4.7-flash` served a session it reached for the Python kernel instead of `terminal`, and the kernel's cwd on the GHA runner is not the repo root, so `open('data/candidates.json')` raised `FileNotFoundError` and the model printed the prompt's missing-input sentinel (`no candidates file`) — 16 of 30 October days, ~100 candidates never judged; Layers 2–4 hit the same bug ("no etp-hermes repo files present", "required inputs missing", "infographic-queue.json is absent"). Belt and braces: each layer prompt now says to use `terminal`/`read_file`/`write_file`, resolve paths from `${GITHUB_WORKSPACE:-$PWD}`, and confirm any missing-input sentinel with `test -f "${GITHUB_WORKSPACE:-$PWD}/<path>"` in `terminal` first.
- Web search provider: web search/fetch is served by the **keyless Parallel Search MCP** (`hermes/config.yaml` → `mcp_servers.parallel`, `https://search.parallel.ai/mcp`, Streamable HTTP). The native `web` toolset (tavily/exa backends) is turned off via `agent.disabled_toolsets: [web]` so Parallel is the *sole* search/fetch surface across all layers; the `hermes -z` oneshot path auto-connects enabled `mcp_servers` and the agent sees `mcp_parallel_web_search` / `mcp_parallel_web_fetch`. Anonymous access = lower rate limits (per-op fail-open in the prompts absorbs throttling); to lift them add an `Authorization: Bearer ${PARALLEL_API_KEY}` header on the server block and seed the secret in `bootstrap-hermes.sh`. The `web:` block + seeded `TAVILY_API_KEY`/`EXA_API_KEY` are inert but kept for one-line rollback (drop `web` from `disabled_toolsets`). A second MCP, **Jina** (`mcp_servers.jina`, `https://mcp.jina.ai/v1`, from github.com/jina-ai/MCP), is also registered keyless as a *fetch* surface — the agent sees `mcp_jina_read_url`/`mcp_jina_parallel_read_url` (URL→Markdown) and can use them when a page resists Parallel's fetcher. - Harness simulate + grade: phase 2 of the self-optimising harness (`docs/self-optimising-harness.md` §4, contract in `docs/harness-interfaces.md`). `scripts/harness/simulate.py` replays a layer prompt (`--prompt-path`) on one provider (`--runtime nvidia|zai|deepseek`, via the runtime switch in `scripts/ab_llm.py` — `chat(..., runtime=)` / `have_key(runtime)`, base URL/key/model per runtime from env, default `deepseek` so existing callers are unchanged) over every active `evals/scenarios/ingest/` card plus a fresh window of `data/replay/<date>.json` snapshots (`--window-days` 14, deduped by normalized URL newest-first, `pre_extracted` skipped, `--limit` cap), using `ab_backfill.py`'s single-candidate user message with an override asking for `{"keep", "company"}`. The live watchlist (`--companies`, default `./data/companies.json` so a reverted worktree replays its own config, else the repo's) is overlaid on the frozen inputs: the matched company's live `description` replaces the card/snapshot one, and its live `exclude_terms` veto the item via `entity_terms.is_excluded` (verdict `drop`, `via: "exclude_terms"`, no model call), so rung-1 config proposals and their prune reverts actually move the replay; `companies_path` is recorded in the output. It records keep/drop/null per item (fail-open), exits 2 when the runtime has no key, and for `agent_supplement`/`synthesis` writes an empty `implemented: false` result. `scripts/harness/grade.py` pairs champion/proposal sim files by runtime and applies the pre-registered rule: every active card passes its graders (`verdict_match`/`blind_judge` = proposal verdict equals the card's judge-derived `expected.verdict`, `company_match` case-insensitive, non-ingest graders pass with a note; pass counts weighted by `scenarios.weight`), no significant window regression (window disagreements labeled by `ab_judge.judge_row` on `--judge-runtime`, default `deepseek`, cached in `data/harness/judge-cache.jsonl` by (url, judge runtime) so reruns and the second sim runtime are free; McNemar via `ab_stats.right_arm`/`binom_two_sided`), keep-volume ratio inside `ab_stats.compute_guardrail`'s 0.5–2.0 band, and `cost_delta` ≤ 0.15 (relative `usage.total_tokens`, 0.0 when absent) — on every runtime, else REJECT. Writes `data/harness/verdict.json` (contract shape) and `data/harness/replay-table.md` (one row per runtime + failing scenario ids). Replay calls use `max_tokens=1024` (reasoning models burned the old 80 on thinking and returned empty `content`), `ab_llm.chat()` prints a one-line stderr diagnostic on every failure (HTTP status + first 300 chars of the error body, exception class, or empty-`content` with `finish_reason`/`reasoning_content` presence) and falls back to `reasoning_content` when `content` is empty, per-runtime extra request body lives in `Runtime.extra_payload` (`zai`: `thinking: {type: disabled}`), and `simulate.py` exits 2 when every verdict is null — or after `--max-consecutive-failures` (default 5) failed calls in a row — so `simulate_and_grade` skips the dead runtime instead of grading all-null sims. The workflow also wraps every simulate call in `timeout $HARNESS_SIM_TIMEOUT_SECS` (default 1500): on 2026-10-18 NVIDIA read-timeouts (4 × 90s per item) stretched one sim past the 6h job limit and the run was cancelled with no verdict. Run by hand on a branch for now; the workflow lands in phase 3. Tests: `tests/scripts/test_harness_{simulate,grade}.py`. Local: `python3 scripts/harness/simulate.py --layer ingest --prompt-path prompts/ingest.md --runtime nvidia --out data/harness/sim/champion-nvidia.json` (repeat per arm × runtime, e.g. `--runtime zai`, `--out data/harness/sim/proposal-<rt>.json` with the edited prompt) then `python3 scripts/harness/grade.py --champion data/harness/sim/champion-nvidia.json data/harness/sim/champion-zai.json --proposal data/harness/sim/proposal-nvidia.json data/harness/sim/proposal-zai.json`.
- Self-optimising harness (memory layer, `docs/self-optimising-harness.md`, contract in `docs/harness-interfaces.md`): production failures are frozen into **scenario cards** — one JSON per failure under `evals/scenarios/<layer>/<id>.json` (committed, append-only; superseded cards get `status: retired`, never deleted), read/written only through `scripts/harness/scenarios.py` (`validate`/`save`/`load_all`/`next_id`/`cluster_key`/`find_by_url`/`find_by_issue`). `scripts/harness/write_scenarios.py` creates them from three fail-open sources: `--from-ab` (the labeled `signals/ab/disagreements.jsonl` rows → `ab_seed` cards; the 73 unique URLs are the seed corpus), `--judged` (judge-vs-pipeline disagreements → `judge_disagreement` cards) and `--labels` (`signals/harness/human-labels.jsonl`, the issue-free human input: an operator appends `{url, company, label, note, date}` lines with `label` ∈ `wrong-keep`/`missed`/`brief-error` → `human` cards, weight 3, idempotent per URL; wired into the "Write scenario cards" step, missing file is skipped) and `--issues` (`gh issue list --json number,title,body,labels,url` output; same labels with a URL and a `Company:` line → `human` cards; only usable on forks with Issues enabled); idempotent per input URL (per issue number for human cards). Three `continue-on-error` steps run right after "Filter seen items" in `hermes-sync.yml`: `snapshot_replay.py` copies `data/candidates.json` to `data/replay/<date>.json` (committed, newest 30 kept) as the replay window for future proposals; `daily_judge_sample.py` re-rules a date-seeded sample of ≤40 kept (today's updates) + ≤40 dropped (candidates absent from the updates) Layer 1 verdicts with the blind `ab_judge.py` prompt → `data/harness/judged/<date>.jsonl` (committed; no `DEEPSEEK_API_KEY` → writes nothing); then `write_scenarios.py --judged` turns that day's disagreements into cards. The `evals.yml` fast job runs `scripts/harness/check_scenarios.py` (schema, filename/layer placement, duplicate ids, duplicate active URLs per layer; exit 1 with the full list), and `evals/**` triggers it on PRs. Jev judge: `scripts/jev_judge.py` calls TypeSafe's Jev classifier (`POST https://api.typesafe.ai/v1/systemone`, `TYPESAFE_API_KEY`, ~$42 per billion input tokens, ~570 input tokens per item) with the item text, company description and the ingest relevance criteria as a `choice` keep/drop question plus a `noul` materiality score, retrying 429/529/timeouts and failing open to `verdict: None`. `daily_judge_sample.py --judge auto` (default) uses Jev when the key is set — judging every kept and dropped Layer 1 item and every Layer 2 kept item (rows carry `layer`, `judge`, `judge_confidence`) — else the ≤40+40 DeepSeek sample; the step runs after Layer 2 and `filter_exclusions.py` so it sees final output. `write_scenarios.py --judged` files rows under `evals/scenarios/<layer>/` (Layer 2 disagreements become `agent_supplement` cards) and skips Jev disagreements below `--min-confidence` (default 0.7). It also skips a judge-keep over a pipeline-drop when the row's `published` (the candidate `pubDate`, carried by `daily_judge_sample.py`) is empty or older than `--max-age-days` (default 30): Jev rates materiality, not recency, so the first run of a new html_scrape source (undated 2024–25 press backlog) minted 17 wrong `false_drop` cards on 2026-10-17/18 (retired with `retired_reason`). Rows without the `published` key (pre-2026-10-19) are unaffected. Calibrate with `python3 scripts/harness/jev_calibrate.py` (agreement against the active ingest cards and against the DeepSeek `verdict_judge` rows, written to `data/harness/jev-calibration.json`); 2026-10-12 baseline was 73.7% on 76 cards overall and 93.5% on the 46 with confidence ≥ 0.7. Nothing consumes the cards yet — the simulator/grader land in later PRs. Tests: `tests/scripts/test_harness_*.py`.
